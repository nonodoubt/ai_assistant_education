# Валидация архитектуры

Этот пакет валидирует архитектуру чат-бота по метрикам, требуемым в главах 2-3 ВКР.

## Состав

| Файл | Назначение |
|---|---|
| `dataset.jsonl` | **200 тест-кейсов**, 123 с ground truth, 51 проблемный, 22 многоходовых |
| `programs_catalog.json` | Канонические названия 32 программ |
| `run_eval.py` | Прогон одной архитектуры через всю базу кейсов |
| `score_eval.py` | Попарное сравнение архитектур + Wilcoxon |
| `build_dataset.py` | Генератор датасета (сохраняет 53 исходных + добавляет кейсы из логов) |

## Происхождение кейсов

Первые 53 кейса — исходный синтетический набор (сценарии A–K). Остальные 147
построены из **реальных запросов пользователей** (`chat_logs.db`, 131 сессия)
с исключением кликов по кнопкам быстрых ответов. Добавлены новые сценарии L–T:
намерение записаться, поиск по педагогу, опечатки, поиск по названию программы,
несоответствие возраста, фильтр по дням, «показать всё», прочие FAQ, несколько детей.

**Ground truth** для новых кейсов сгенерирован механически из `knowledge.db`:
программы нужного направления, чьи возрастные рамки включают запрошенный возраст
(для дневных запросов — дополнительно по расписанию; для платных — по `is_free`).
Имена — из канонического каталога. Скрипт-генератор: `build_dataset.py`.

## Запуск (из корня проекта)

```bash
python validation/run_eval.py --arch <название_архитектуры>
python validation/run_eval.py --arch baseline --limit 5   # отладка
```

На выходе: `validation/eval_results_<arch>.jsonl` + сводка в консоль.

## Сравнение архитектур

```bash
python validation/score_eval.py \
    validation/eval_results_baseline.jsonl \
    validation/eval_results_synonyms.jsonl \
    validation/eval_results_hybrid.jsonl \
    validation/eval_results_hybrid_rerank.jsonl
```

## Метрики

**Retrieval (только `evaluate_retrieval: true`):** P@3, P@5, R@3, R@5, MRR, nDCG@5
**Системные:** латентность (median/p95/mean), LLM-вызовы, исключения, auto-pass.

**51 проблемный кейс** (`problem_case: true`) — это реальные трудные запросы из
логов и истории разработки (опечатки, короткие токены вроде «изо», несоответствие
возраста, многоходовое накопление состояния, парсинг дней). Главный показатель —
сколько из них пройдено на новой архитектуре.

прочитай `actual_response` для 30 кейсов, поставь 1-3, усредни.
